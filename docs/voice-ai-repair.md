# 安卓语音与 AI 音色修复记录

## 已确认根因

1. **AI 输出采样率被错误标记**：OpenVoice 模型固定输出 22,050 Hz PCM，但活动层沿用输入采样率。48 kHz 录音或 44.1/48 kHz 文件会以错误时间轴试听和导出，表现为明显加速、升调及音色异常。
2. **源音色向量跨输入污染**：`sourceEmbedding()` 使用固定键 `source` 进入缓存，同一 Activity 的后续录音、导入或合成语音会复用第一段输入的源说话人向量。
3. **文字与变声原本是分离入口**：旧文字工具在 LocalToolsActivity 内；本轮合并时将 048 路由到 AiVoiceToolsActivity，并同步补齐 supports(048) 与 TTS → 变声链路。路由缺口是在集成过程中修正的，不作为旧版文字工具原本不可用的证据。
4. **录音失败后状态可能锁死**：操作 busy 标志先置位，采样率探测却在异常回收范围外；探测失败后页面会一直认为已有任务。启动后也没有确认 `AudioRecord` 真正进入录音态。
5. **内置参考音色采样率错误**：实际参考 WAV 为 16,000 Hz，旧预设脚本直接送入按 22,050 Hz 配置的声纹提取模型，没有重采样。已用同一批本机系统 TTS 合成参考语音重新提取三个向量，明确记录原采样率与模型采样率。

## 修改

- `VoiceProcessor` 增加输出采样率契约；OpenVoice 明确返回 22,050 Hz，DSP 保持输入采样率。试听、时长和 WAV 头统一使用处理器实际输出采样率。
- 当前输入的 source embedding 每次重算，只保留稳定参考向量缓存。
- 048 支持文字输入：系统 `TextToSpeech.synthesizeToFile()` 生成应用缓存音频，再复用与导入文件相同的解码及 OpenVoice ONNX 转换。系统 TTS 不是 AI 音色，AI 转换仍由 OpenVoice 完成。
- 048、V01、V02 使用同一个 `OpenVoiceProcessor` 音色集合；所选 AI 音色保存在应用私有偏好中，跨三个入口恢复。
- AI Activity 默认展示真实 `AI 音色` 引擎，同时保留明确标名的 `本地 DSP` 备选，不把 DSP 称作 AI。
- 录音初始化、启动、工作线程提交均纳入失败回收；只有 `RECORDSTATE_RECORDING` 后才显示录音中。按 MIC、VOICE_RECOGNITION、DEFAULT 顺序尝试兼容音源，全部失败时报告麦克风被占用或不可用，并允许重试。
- 取消、离页、销毁会停止 TTS/录音/试听并清理临时合成文件。

## 最小验证

- 语音相关 Java 源码连同 Android 36 API 与 ONNX Runtime 1.20.0 API 做定向 `javac`：通过，仅有 Android 弃用 API 提示。
- `VoiceSelfTest`：28 项通过。覆盖 DSP 时长/音调/速度/数值范围/取消，以及 048 接线、处理器输出采样率、TTS 文件合成入口、源向量不跨输入缓存、AI 音色共享状态。
- 未运行全量 Gradle、未启动模拟器。

## 验证边界

- 当前没有真机证据，不能声称已验证具体手机的麦克风权限/AppOps、并发占用、厂商音频源兼容性、系统中文 TTS 数据或 154 MB ONNX 模型的速度和峰值内存。
- 文字语音的基础发音取决于设备系统 TTS；随后目标音色转换为真实 OpenVoice 推理。系统没有中文 TTS 数据时会明确失败，不会用 DSP 或静音冒充。
- 不支持向游戏、通话或第三方聊天应用直接注入虚拟麦克风，也没有实时耳返。
