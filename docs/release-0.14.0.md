# 拾用 0.14.0：阅读中心（小说 / 漫画 / 视频）

底部「阅读」现在是一个三合一的内容中心，不再是一个空的占位页。装好后打开「阅读」，顶部有三个标签：小说、漫画、视频。

## 怎么用

1. 第一次进「阅读」，点右上角「源管理」→「拾用精选」→「获取」。13 个源会先以差异预览列出来（新增 / 更新 / 未变 / 冲突），确认后导入。断网时可以直接用内置快照预览。
2. 回到首页，选好标签，输入书名/漫画名/视频名，点搜索。几个源会并行搜，结果陆续出现，哪个源慢或挂了都不会卡住其它源。
3. 点结果进入详情：小说看目录和正文，漫画看章节图，视频选集数。
4. 阅读/观看进度自动记录，下次从「继续阅读」/「继续观看」接着来。可以加收藏。

这些不是"从网上抄来直接塞进去"的规则：每一个都在客户端同一个引擎里跑过完整链路（搜索→目录→正文/图片/播放地址）。视频源拿到的是真正的 `.m3u8`，不是播放不了的网页。

## 规则兼容性

书源规则按 Legado 的常用子集实现：CSS 选择器（含 `@text`/`@href`/`@src` 后缀与链式写法）、JSONPath、XPath、正则替换（`##`）、`||` 回退、`&&` 拼接、`@put`/`@get` 变量、`{{...}}` 模板、`@js:` 与 `<js>` 脚本。

脚本跑在一个受限的 Rhino 解释器里：只放行基础 Java 类型、`Math`、`Base64`、`Arrays`、集合和 `javax.crypto`；`File`、`ProcessBuilder`、`Runtime`、`java.net.URL`、`System.getenv`、`Class.forName` 都被挡在类白名单外，另有正则拒绝 eval/Function/反射/死循环等构造。单脚本 8 秒墙钟上限。

## 这一版修掉的坑

- JSON 书源的 `@js` 规则读不到字段（`result.id` 恒为 `undefined`），导致漫画章节 URL 全是 `c=undefined`。
- 脚本指令计数器跨脚本累计，跑几个源之后任何脚本都会"莫名超限"。
- 纯 JS 的 AES 解密被 1M 指令上限卡死。
- 视频源只取了 CMS 的第一条线路（网页 `/share/` 页），ExoPlayer 打不开；现在 `.m3u8` 优先。
- 番茄小说的搜索结果是音频专辑和文字书混在一起的，音频行没有阅读页，现在直接跳过。
- `ruleBookInfo.tocUrl` 里 `java.put` 的变量在同一本书的目录阶段读不到。
- 网络层：部分站的 HTTP/2 被中间设备挂死而 HTTP/1.1 正常，另一些反着来；现在 h2 优先，读阶段卡住 18 秒内自动降级 h1 重试一次。
- 服务端：夜间任务只发布本轮测过的源，会把 13 源包缩成 1 源；现在未测到的旧源原样带过，4 个视频 CMS 也写进了固定种子。
- 服务端：`finalize_sources.py` 用 `mkstemp` 重写发布包，默认 `0600` 把 `curator` 设好的 `0644` 盖掉，导致每次抓取后 hub 502。

## 已知边界

- 4 个源（筆趣閣、拷贝漫画、最大资源、无尽资源）在当前网络下被目标站点封锁（TCP 超时 / TLS reset / 无路由 / Cloudflare 403），没有放进内置包。换网络环境可能可用，服务端验证通过会自动回归。
- 番茄小说免登录只能完整读前 10 章，之后是付费片段；这是站点策略，没有绕过。
- 视频源是公开的 Apple CMS 聚合接口，只提供播放地址，不代理、不缓存媒体流；能不能播还取决于上游。
- 视频源线路里的 `.m3u8` 由第三方 CDN 托管，跨境线路的加载速度不受本应用控制。
- 书源是第三方的公开规则，站点改版后会失效。失效的源在服务端会保留上一次可用的版本，不会因为一次失败就被删掉。
- 站点偶尔会用 Cloudflare 挑战拦人（实测无忧书城会间歇性返回 `Just a moment...`）。这不是规则失效，过一会儿或换个出口就恢复；客户端会明确报 `HTTP 403` 而不是假装成功。
- 部分站点在当前网络下 HTTP/2 会被中间设备挂死、HTTP/1.1 正常（另一些正好相反）。客户端已改成 h2 优先、读阶段卡住就自动降级 h1 重试一次。

## 服务端

机器 01 上的独立服务每天 04:17（±30 分钟）抓一遍候选源、跑真实链路测试。它只做**增量**：这轮验证通过的新源加入，失败的源保留上一次可用的条目，本轮没覆盖到的旧源原样带过（`carriedOver`），所以 13 个随包基线不会被夜间任务抹掉。服务端**不执行**任何上游脚本。权限上它用独立的 `pk-content` 用户，读不到 Hub 的管理口令。
