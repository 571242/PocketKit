# 拾用 0.4.0：独立连点器

## 安装

使用 [新版 APK](../dist/PocketKit-0.4.0.apk) 覆盖安装，不要先卸载。此包与此前 0.3.0 使用相同包名和本机调试证书；版本号提升至 12。它仍是开发签名包，不是经过商店审核的商业发行版。卸载会删除私有脚本和其他工具的数据；重要脚本请先手动导出。

## 这次改变

- 首页底部固定的“连点器”是独立大模块，不再出现在普通工具分类、常用或最近网格里；其他工具保留。
- 取点立即提供可拖动的悬浮控制条，通知不再是必须寻找的入口。切到目标应用，点“开始取点”，选中后确认保存；可以重选、取消。取消不会修改原坐标。
- 快速连点：填次数和间隔，选择真实位置，从悬浮条手动开始。次数为 0 表示持续运行；未完成取点的任务在模型层禁止执行，取消会清理本次未完成任务。
- 单指录制：点击、长按、曲线滑动、返回与主页动作；支持暂停、继续、撤销最近动作、完成或取消。已有脚本编辑页可以继续追加录制。
- 已完成的录制动作会写入独立“未完成录制”恢复草稿。正常完成才替换原脚本；取消不改原脚本。系统异常中断时，回到脚本列表查找恢复草稿；正在进行或尚未写入成功的最后一个动作不能保证恢复。
- 编辑器默认显示紧凑步骤摘要，展开才显示参数。支持上移、下移、递归复制、删除及高级设置。折叠前校验输入；手工修改滑动坐标会清除旧录制轨迹。
- 播放悬浮条支持开始、暂停、继续、停止后重跑和关闭。音量下键停止后续动作。无障碍断开时停止相关服务；显示清楚的权限状态、错误信息和后台设置指引。

## 建议先这样验收

1. 覆盖安装，打开首页底部“连点器”。按权限区的“设置”打开无障碍服务与悬浮窗，返回后确认状态更新。部分 Android 13+ 侧载安装需在系统应用详情中手动允许受限设置；只对自己信任的安装包操作。
2. 在无风险页面先做快速连点：次数 3，间隔 500 毫秒。开始取点、选中目标、保存，确认控制条保持“待开始”，再点开始。随后测试停止、重跑、音量下键和取消取点。不要用购买、支付或转账页面测试。
3. 新建录制，先切到目标应用再点悬浮条开始。逐次录入点击、长按、滑动；每次松手后等待“已录”再做下一次。试一次暂停、继续、撤销，再点完成；回到编辑器核对动作和坐标，然后从目标页面回放。
4. 再试取消、屏幕旋转、关闭无障碍后返回，以及前后台切换；应该提示而不是无反应。若系统强杀录制服务，检查“未完成录制”草稿。旋转后应重新取点，录制与回放尽量使用相同方向、分辨率和页面布局。

## 必须知道的边界

- 这是覆盖触摸层捕获后再执行的单指录制：松手后才向目标应用发送真实动作，不是全局透明监听。长按/滑动会经历捕获和实际执行两个阶段；执行中要等待，不要连续抢点。
- 保存轨迹和总时长，不能保证逐采样点速度完全还原。不录键盘输入、系统手势导航或多指缩放；返回、主页请用录制条按钮。单次录制手势最长 10 秒，最多新增 500 个动作；手工设置的执行手势最长 60 秒。
- Android 已接收的当前系统手势不能撤回；暂停或急停阻止后续动作，不保证立刻终止正在进行的长手势。时间间隔有系统调度、手势回执和应用反应开销，不是精密定时器。
- 坐标脚本无法判断按钮含义或支付安全性；不会绕过安全窗口、验证码或系统授权。未绑定目标应用时，必须由你确认当前前台页面。
- 自动返回编辑器可能被厂商后台弹出限制阻止，此时自行返回“连点器”查看结果；结果状态仍保存在本机。系统省电、熄屏或后台限制可能中断服务。

## 实际验证范围

最终构建完成：`assembleDebug`、`lintDebug`、`testDebugUnitTest`、`assembleDebugAndroidTest`。Lint 没有错误，仍有工程警告；未把“构建通过”写成“零警告”。显式执行并通过的离线检查是核心执行器、录制会话、JSON 编解码兼容性及两组界面接线 contract 检查。界面 contract 是源码约束检查，不是触屏或截图测试；Gradle 测试任务成功也不代替这些显式自测。

APK 的版本、最低系统版本与签名已核验；与 0.3.0 的证书摘要一致。旧 v1 脚本导入、普通脚本导出及新轨迹往返通过本地测试；带轨迹的新脚本不保证可被旧版应用导入。

**没有连接真机；现有模拟器缺少加速驱动，软件启动失败。悬浮层实际显示、厂商权限联动、触摸落点、录制回放、音量键和长时间稳定性均尚未真机验证。没有运行 connected instrumentation、Release/R8、商店上架或商业合规验收。请先按上面的无风险场景试用。**

检查日志和构建元数据见 [验证记录](../evidence/autoclicker-040/verification.json)。需要复核时，使用 [离线自测脚本](../tools/automation-selftest/run.sh)，为它提供本机既有的 org.json JAR；没有引入新的应用运行时依赖。

对指定参考包仅做 REA 文件审计、清单和资源的静态核对，借鉴权限引导、悬浮控制与录制流程的组织方式；没有运行其 APK，没有得到解壳后的业务实现，也没有复制代码或素材。参考证据见 [静态证据记录](../evidence/autoclicker-040/reference.md)。

旧版取点问题的源码依据：准备条只在 Android 13+ 且通知权限未授予时出现；其他情况下主要由通知上的“开始”进入实际采集。因此点击编辑器按钮后可能只进入待采集，缺少直观反馈。新版始终提供可见入口并显式返回保存、取消或错误结果。这是可确认的静态缺陷修复，不是声称已在用户手机复现并验证所有成因。
